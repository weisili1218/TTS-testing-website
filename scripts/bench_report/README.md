# 批次跑測的離線分析

平台跑完批次只給你「這一批的摘要」。要做**跨引擎、跨批次**的比較還缺三件事，
這個套件補上：

| 缺的東西 | 誰負責 |
|---|---|
| 寬鬆 CER —— 把簡繁與數字書寫形式的雜訊扣掉 | `lenient_cer.py` |
| 成對顯著性檢定 —— 差距是真的還是抽樣抖出來的 | `significance.py` |
| 把多顆引擎的逐句數據對齊、組成報告資料 | `build.py` |

## 安裝

```
make install-bench            # 或 pip install -r requirements-bench.txt
```

只多一個 `zhconv`（做簡繁轉換）。平台本身與 CI 都不需要裝。

## 用法

```
python scripts/bench_report/build.py \
    --engine fun-cosyvoice3=batch-260828-172718 \
    --engine qwen3-tts=batch-260826-150024 \
    --engine f5=batch-260826-150024 \
    --baseline 0.1864 \
    --out storage/reports/compare.json
```

`--engine KEY=BATCH` 可以重複，順序就是報告的呈現順序。同一顆引擎只能給一次。
不同引擎可以來自不同批次 —— 題目用**文字內容**對齊，對不上會直接中止。

`--baseline` 是 ASR 的誤差底線（拿真人參考音自己送 ASR 量到的 CER），
用來把逐句結果分級。不給就當 0。

## 讀結果的三個提醒

**一、CER 兩版都要看。** 嚴格版把「ASR 寫簡體」「ASR 改用阿拉伯數字」都算成錯，
會系統性高估錯誤率，而且對不同引擎高估的幅度不一樣 —— 足以翻轉名次。
輸出裡每一句都有 `c`（嚴格）與 `cl`（寬鬆），`tests.sml` 是兩者的落差。

**二、跨批次的速度不能當同場結果讀。** 引擎不是同一批跑的時候，
`meta.sameBatch` 會是 `false`，CLI 也會印警告。同一批裡平台會逐句輪替、
隨機決定誰先跑，把「先跑的比較冷」消掉；跨批次沒有這層保護。

**三、p 小不等於差距大。** 差距多大看 `ci`（差值中位數與 95% 區間）
與 `effect_r`。三顆以上引擎兩兩比就是多重比較，這裡刻意不做 p 值校正。

## 已知落差

`lenient_cer.py` 這份正規化定義是 2026-08-28 整理的。在那之前有一次性腳本算過
一版寬鬆 CER，100 格裡有 10 格對不上（多數差在 0.01 以內，最大 0.09），
舊定義已經找不回來。**同一份報告裡所有引擎務必用同一份定義重算**，別新舊混比。
嚴格 CER 直接取用平台存下來的值，不受影響。
